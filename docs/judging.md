# Judging

Port of legacy `CarJudging`, `public/js/judging/*`, the `car_judging*` views, `Admin\Controllers\JudgingList`
and the carShow `is_judging_released` / `send_judging_results` admin actions.

## Judging id (QR codes and emailed links)

`App\Support\Judging\JudgingId` reproduces legacy `CarJudging::makeId/getId`: single DES-CBC, key
`"judging\0"` (the 7-byte key zero-padded, as OpenSSL did), IV `12345678`, PKCS#7, base64, `urlencode`, then
`%` -> `lpct`. OpenSSL 3 has no DES, so the cipher is phpseclib 3 (`phpseclib/phpseclib` 3.0.57, used for DES only).

- `tests/Fixtures/judging-id-vectors.json` holds real legacy output: ids 1-2000 plus large ids, generated by
  running the verbatim legacy functions under PHP 7.4 / OpenSSL 1.1.1n. `JudgingIdTest` checks encode and decode
  against every vector and the FIPS 46 DES test vector.
- Decoding differs from legacy on purpose. Legacy also turned `leq`/`lamp`/`lfs` back into `=`/`&`/`/`,
  which `makeId` never emits, so ids whose ciphertext contained those letters never decoded (25 of the first
  300000, e.g. 1121). Now only `lpct` + `2B|2F|3D` is reversed and a result is accepted only if it re-encodes to the
  exact input. Those 25 vectors are in the fixture and now work.
- Plain digits are accepted as the id itself (legacy did the same). The id is not a secret: authorization is
  always checked.

## Pages and JSON (`routes/web/judging.php`)

| Path | What | Who |
| --- | --- | --- |
| `GET judging/{id}` | SurveyJS scoresheet page (Vite entry `resources/js/judging/judge.ts`) | gate `judge-car` |
| `GET judgingData/{id}` | `{form: [pages], showPage}` (legacy shape) | `judge-car` |
| `POST judgingSubmit/{id}` | autosave / page save / photo upload / photo delete (legacy keys `q_`, `qtr_`, `comment_`, `file_[]`, `delete_file_[]`) | `judge-car` |
| `GET judging_answers/{id}` | judging summary | gate `judging-answers` |
| `GET judging_draw/{show}` | top 5 per "body + type" | gate `judge-for-show` |
| `GET judging_qr_code/{id}` | QR PNG of `{APP_URL}/judging/{id}` | `judge-for-show` (car's show) |
| `GET judging_qr_code/show/{show}` | QR sheet PDF, one landscape A4 page per judged car | `judge-for-show` |

- `judge-car`: admin, or a judge assigned to the car's show (`car_show_judge`) who does not own the car.
- `judging-answers`: `judge-car`, or the owner once `CarShow::judgingResultsVisible()` (released, or `date_end`
  before today, the same rule the car profile used for `judgingLink`). Legacy let any judge, and the owner at any
  time, open this page.
- Guests on the HTML pages go to `/#/login?redirect=<path>`; `/judging_answers/` and `/judging_draw/` were added to
  the SPA's full-page redirect prefixes. Denied users get a 403 page with a sign-out form. JSON answers 401/403
  `{errors: [...]}`.
- Legacy `POST judging/login/{id}` is gone: sign-in goes through the SPA.
- The car profile `judgingLink` (owner view) is now filled with the answers URL when results are visible and the
  car has answers.

## Scoring (`App\Services\Judging`)

- `JudgingSheet`: questions of the first form of the car's judging type (legacy `hasOne` on `type_id`), ordered page,
  sort_order, id; SurveyJS JSON as legacy (`q_`, `qtr_` for `has_quarter`, `comment_`, `file_` with `sourceType:
  file-camera`); `showPage` = first page with an unscored question.
- `JudgingSubmission` keeps legacy rules: score + quarter capped at 10; a quarter alone applies to the stored whole
  score; a later page cannot be saved while an earlier page has an unscored question (400 with
  `firstIncompletePage`); the answer's `user_id` is the last judge; an answer row is created for photo-only
  uploads. Added: the score must be one of the question's allowed values, quarters only on quarter questions
  (0/.25/.5/.75), comments latin1 and <= 65535; saves for one car run under a row lock on `show_registration_car`.
- `JudgingScores`: one query for the admin list, draw and QR sheet. Score = sum of live answers on forms of the car's
  type; `num_empty_questions` = questions with no live answer row (legacy SQL). Draw ties: another car in the same
  group (placed or not) has the same score; incomplete cars show "Incomplete".

## Photos

`JudgingPhotos` stores `public/images/judging/{carRegId}/{questionId}/{time}_{uniqid}.jpg` through
`ImageStore::storeAs()` (new): content-sniffed, size/frame limits, first frame only, EXIF orientation applied,
re-encoded JPEG with metadata stripped, atomic write, no shell. Deletes accept only plain `name.jpg` names inside
the question directory. Photos are listed from disk (the `show_registration_car_judging_image` table stays unused,
as in legacy). The client shrinks photos to 2048x1536 before upload; the server re-encodes everything anyway.

Client photo UX (kept from legacy `public/js/judging/index.js`): each file question gets **Take photo** (rear
camera, `capture=environment`) and **Choose from gallery** (multiple) buttons above SurveyJS's own chooser
(`photoButtons.ts`). Uploads go one request per photo with byte progress and abort (`postWithProgress`); the
transfer bar (`TransferStatus.vue`, fed by `UploadTracker` in `uploads.ts`) shows "Uploading images: X left, ETA",
per-file percent, "Upload stalled" after 15 s without progress, failed files ("Upload failed — try again"), and a
**Stop photo uploads** button. Moving to a later page or completing is blocked while photos upload, with the legacy
message. A save slower than 5 s shows "Realtime save delayed. Weak connection.".

## Admin API (`routes/web/admin/judging/judging.php`, all under `/admin-api/judging`)

The judging route group is **default deny**: `routes/web/admin.php` loads `routes/web/admin/judging/*.php` with
`auth + judge_or_admin + judge_for_show`. Every route must take a `{show}` route parameter; `EnsureJudgeForShow`
reads the show only from the route parameter (`show`, else `show_id`), never query or body input. The single
show-less route, `GET shows`, opts out with `->withoutMiddleware('judge_for_show')` and lists only the caller's
shows. `JudgingAdminTest` scans all routes so a new judging route without the scope fails the build.

| Method | Path | Notes |
| --- | --- | --- |
| GET | `shows` | admins: all shows; judges: assigned shows |
| GET | `shows/{show}/entries?judging_type_id=` | judged cars with counts, score, judging/answers/QR URLs |
| GET | `shows/{show}/unjudged` | registrations with cars that have no judging type |
| GET | `shows/{show}/types?body_id=` | types offered for the body (`judging_show_body`) |
| POST | `shows/{show}/entries` | set a car's type; registration must be in `{show}` and the type offered for its body |
| DELETE | `shows/{show}/entries/{entry}` | clear the type (entry must be in `{show}`) |
| GET/POST/DELETE | `shows/{show}/judges[/eligible][/{user}]` | admin only; judge-type accounts only |
| PUT | `shows/{show}/release` `{released}` | admin only |
| POST | `shows/{show}/results-mail` | admin only; 409 until released; queues one `JudgingResultMail` per judged car with answers |

Legacy `addJudging`, `removeJudging` and `getDraw` were not scoped to a show, and the `/admin2/judging_list` filter
took the show from `show_id` input or any path ending in `judging_list`; all fixed above.

Vue admin page: `resources/js/pages/admin/judging/` (`/#/admin/judging`, minLevel 2; event judges and results
sections show for admins only). Registry line, to add in the Event block of `resources/js/admin/registry.ts`:

```ts
{ key: 'judging', label: 'Judging', group: 'Event', path: 'judging', component: () => import('../pages/admin/judging/JudgingPage.vue'), minLevel: 2 },
```

- composer: `phpseclib/phpseclib` 3.0.57 (+ `paragonie/constant_time_encoding` 3.1.3, `paragonie/random_compat`
  9.99.100), `chillerlan/php-qrcode` 6.0.1 (+ `chillerlan/php-settings-container` 3.3.0). `composer audit`: none.

  The judging bundle is ~1.7 MB (400 KB gzip), loaded only on `/judging/*`.
